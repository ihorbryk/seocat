# 0005. Images вимірюються з завантаженого ресурсу, без host permissions

Статус: прийнято (2026-11-03), змінено того ж дня: вага з HTTP-кешу

## Контекст

Group Images показує для кожного Image адресу, розміри в пікселях і вагу файлу. За ADR 0003 Metrics рахуються зі структури DOM, але розміри й вага існують лише в завантаженого ресурсу. Дозволи розширення — лише `activeTab` і `scripting` (ADR 0001), тож попап не може сам запитати чужий файл.

## Рішення

- Адреса Image — `currentSrc` (файл, який браузер вибрав зі `srcset` і завантажив), а якщо він порожній, то абсолютний `src`. `data-src` та інші нестандартні lazy-атрибути не читаються.
- Розміри — natural (`naturalWidth×naturalHeight`), а не розмір показу на сторінці.
- Вага — `encodedBodySize` з Resource Timing (`performance.getEntriesByName`). Вага `data:` URI обчислюється з самого URI.
- Якщо Resource Timing дає 0 або запису немає, вага — розмір відповіді `fetch(src, { cache: 'force-cache' })` зі сторінки (не більше 3 с). Safari віддає нулі в `encodedBodySize`, `decodedBodySize` і `transferSize` для кожної картинки з кешу, навіть same-origin, тож без цього кроку на вже відвіданому сайті всі Images були б Size unknown. `force-cache` бере файл з HTTP-кешу, тому картинка зазвичай не завантажується вдруге. Однакові адреси читаються один раз.
- Якщо файл не завантажено, наприклад lazy-картинка нижче першого екрана або бита, Image має стан Not loaded. Екстракція нічого не довантажує і не змінює Page.
- Якщо браузер не віддає вагу жодним способом (cross-origin без `Timing-Allow-Origin` і без CORS, помилка або таймаут `fetch`), Image має стан Size unknown.
- Host permissions (`<all_urls>`) з `fetch`/`HEAD` з попапа відхилено. Вони майже завжди дали б вагу, але Safari питав би доступ до сайтів, а це суперечить ADR 0001. `fetch` зі сторінки спершу відхилили, бо cross-origin файли однаково блокує CORS, а картинка завантажувалася б удруге. Він повернувся лише як запасний крок після Resource Timing і з `force-cache`, коли з'ясувалося, що Safari обнуляє вагу кешованих файлів.

## Наслідки

- Для картинок з CDN на іншому домені без CORS-заголовків вага буде Size unknown.
- Екстракція асинхронна: `run` і `extract` Images повертають Promise; як попап на нього чекає, описано в ADR 0001.
- Вага з кешу — розмір тіла після розпакування (`blob().size`), а не байти передачі. Для файлів, які сервер стискає (зокрема SVG з gzip), у Safari вона більша, ніж `encodedBodySize` у Chrome; PNG, JPEG і WebP зазвичай не стискають, тож для них числа збігаються.
- Якщо файлу вже немає в HTTP-кеші, `force-cache` завантажує його з мережі вдруге. DOM Page від цього не змінюється.
- Результат залежить від того, що браузер уже завантажив: та сама Page до і після прокрутки дає різні знімки.
- Екстракцію Images не можна повністю перевірити в jsdom, бо там немає завантаження ресурсів і Resource Timing. Тести підставляють ці значення.
